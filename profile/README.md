<p>Claude稳定访问住宅IP线路，最常见的错误是把三个指标混在一起看。带宽、路由、丢包，三者的表现和解决方式完全不同，混着看只会得出线路不行的模糊结论，然后换一条，问题再来一遍。</p>

<p>先说带宽。测带宽要看方向，住宅线路的上行通常是瓶颈，而多数业务请求是发出去的。还要看是独享还是共享，共享带宽在高峰期会被同线路其他用户分走，标称值只能当上限看。</p>

<p>再说路由。路由决定延迟和绕行。同样的距离，走得直延迟就低，绕几个中转就翻倍，而且抖动更明显。路由信息一般不公开，只能通过连续测试推断，比如看延迟的稳定性、看不同时段的差异。</p>

<p>最后说丢包。这是最容易被忽略的一项。延迟高一点还能忍，丢包会直接表现为请求失败。丢包往往出现在晚高峰，和带宽拥塞同源，所以看到丢包先查带宽是不是到了上限。</p>

<p>三项分开测，才能知道问题出在哪。带宽足但丢包高，不适合稳定业务；延迟低但带宽窄，不适合重负载；三项都中等，反而可能是最实用的，因为瓶颈都不极端。</p>

<p>测的时候要跨时段。只在一个时段测，结论往往偏乐观，因为问题都藏在高峰期。建议至少覆盖一个空闲时段和一个高峰时段，最好再跨天。</p>

<p>最后，把三项数据记下来，形成这条线路的画像。后面换线路时，就有了可比的基础，而不是每次凭印象判断。</p>
